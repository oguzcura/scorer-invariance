## 1. Pre-registration format (the binding artifact)

- Lives at repo root as `pre-registration.md`; a per-run snapshot under `notes/` dated
  `pre_reg_<scope>_<date>.md`.
- Header block: `**Frozen BEFORE the run.**` + first-write date, author (`oguzc`), design
  parent (the design notes file by section), pilot context (dated pilot report), and any
  user approval with its date.
- Hard line, verbatim style: *"Nothing in this file may be changed after the run starts.
  The analyzer and report generator implement exactly these rules."*
- Structure of the root design doc (§-numbered):
  0. PRE-REGISTRATION banner with freeze date;
  1. Research question (single sentence) + hypotheses — **H0 null stated formally, H1
     directional, plus an explicit honest-negative commitment** ("H0 is a defensible,
     citable finding — not a failed experiment");
  2. Design grid (benchmarks × models × probes, applicability N/A notes per cell);
  3. Probe/method definitions with thresholds as concrete numbers;
  4. Sampling & statistics (exact test named, correction family named);
  5. Expected-results table skeleton (honest-negative wording pre-written);
  6. Execution timeline; 7. Paper skeleton; 8. Reference pack (arXiv-ID-verified);
  9. Appendix provenance.
- Per-run pre-reg (`notes/pre_reg_full_*.md` pattern): §0 scope & planned volume **with
  real numbers from a dry-run** (planned calls, cost estimate + hard cap); one § per
  mandated fix, each with **motivation (data fact verified pre-run) + frozen rule +
  scope**; final § pre-registered statistics; closing italic line: *"End of
  pre-registration. Frozen before launch; the analyzer (...) and report generator (...)
  are the mechanical implementations."*
- Every rule is checkable: thresholds, family sizes, denominators, and tie-breaks written
  out so an analyzer script can implement them mechanically.
- Freeze mechanics for the new project (extension of the old "frozen file" practice):
  sha-256 self-hash recorded at freeze, freeze commit in git, and **append-only
  amendments** — any post-freeze change is a dated appended `## Amendment N` section
  that never edits existing text.

## 2. Results reporting format

- Results file embeds the pre-registration **verbatim** at top under
  `## 0. PRE-REGISTRATION (verbatim, frozen before the run)` before any results.
- Mandatory run-integrity line: run_start/run_end markers, elapsed, **"this run was
  RESUMED/INTERRUPTED"** stated explicitly.
- Tables for spend (per-model calls/ok/fail/retries/tokens/cost) and per-benchmark
  reliability; then **every cell shown, no omission**.
- Honest-negative wording fixed in advance: "no significant contamination detected";
  ambiguous outcomes get a special label, never upgraded (house precedent:
  THRESHOLD-DEPENDENT, never "contaminated").
- Claims ↔ data: every number in prose traces to a JSON/JSONL in `results/` with a
  dated filename; pilot→full consistency checked explicitly.

## 3. Reproducibility practice

- Data snapshots in `data/` + `manifest.json` (machine-readable provenance: source,
  items, schema, note; regenerated by a script; verified-live notes even for empty
  splits).
- Fixed seed (42) stated everywhere sampling happens.
- `verification_pass_*.md`: submission-readiness checklist (DONE / BLOCKING /
  NON-BLOCKING) on top, then claim-vs-verified tables: stats rerun vs paper numbers
  (exact-match ✓), citation audit (every BibTeX entry resolved via arXiv API, title
  verbatim), README reproduction commands executed one by one.
- README reproduction section: numbered `uv run python ...` commands, each mapping to a
  committed results file ("matches results/smoke_*.jsonl"); API keys never committed.
- Matcher/harness parameters published as JSON alongside the labels that measured them
  (`results/ragturk_matcher_labeled.json`: n=106, confusion incl. by-level histogram).

## 4. README style (repo root)

- One-paragraph what/where (artifact repo for paper X, sibling link).
- Status line with date + headline result; link to paper and full-results note.
- **Repository structure table** (path | contents).
- Key-results table (per-cell verdicts with ✅/⚠️).
- Method summary referencing pre-reg § numbers.
- Validation/positive-control section.
- Reproduction commands; Spend table (per run, per model, totals, cost-cap note).
- **"Known honest limitations"** — bulleted, concrete, includes disclosed weaknesses
  (matcher precision-first/low recall, M1 confound, no M3 executed, sample size,
  interruptions).
- MIT license line.

## 5. CI practice

- `.github/workflows/tests.yml` on push+PR+dispatch: **API-free** statistical hand-check
  — synthesize a JSONL log, run the real analyzer over it, `assert` Wilson CI / exact
  test / correction family against hand-computed values; `uv sync --frozen`, Python 3.11,
  astral-sh/setup-uv with cache. Working-directory scoped to `harness/`.

## 6. Paper practice

- LaTeX under `paper/`, compiled with **tectonic**; review option
  (`\usepackage[review]{acl}`) for double-blind; PDFs gitignored; stale drafts
  QUARANTINED, not deleted.
- Author-line policy: real name, "Independent Researcher", reachable email, GitHub
  handle — never noreply.
- Section pattern (paper2.tex): Introduction → Related Work (contamination detection /
  non-English auditing / pre-registration & methodology / honest reporting) → Method
  (benchmarks, artifacts, models, probes, consensus & adjudication, pre-registration
  pointer) → Results (run reliability first, then per-benchmark with every cell, then
  adjudication summary) → Discussion (what the distinction means, honest negatives as
  contributions, positive control) → Limitations → Reproducibility statement.
- References: arXiv-ID-verified pack (10–15 entries), no unverifiable citations.
